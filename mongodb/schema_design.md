# Документная модель — домашнее задание 04

Вариант 9: электронная почта. База MongoDB называется `maildb` и содержит
три коллекции: `users`, `folders`, `messages`.

## Пользователи: users

```javascript
{
    _id: "10000000-0000-4000-8000-000000000001",
    login: "user01",
    first_name: "Ivan",
    last_name: "Petrov",
    password_hash: "$argon2id$v=19$m=65536,t=3,p=4$cjrweZivnffTJhze9PgvSg$luEiJ2OeKObGJmBAkKnjePH4CycsfgI4pcweBQTL6Ls",
    created_at: ISODate("2026-10-12T12:00:00Z")
}
```

`_id`, логин, имя, фамилия и хеш — String; `created_at` — BSON Date.
Логин API приводит к нижнему регистру. Уникальный индекс `login` предотвращает
повторную регистрацию. Пароль хранится как хеш Argon2id и не возвращается через API.
Хеш в примере принадлежит учебному паролю `example-password`.

## Папки: folders

```javascript
{
    _id: "20000000-0000-4000-8000-000000000001",
    user_id: "10000000-0000-4000-8000-000000000001",
    name: "Inbox",
    created_at: ISODate("2026-10-12T12:00:00Z")
}
```

`_id`, `user_id`, `name` — String; `created_at` — Date.
`user_id` ссылается на `users._id`. Индекс `{user_id: 1, name: 1}` уникален:
у одного владельца не может быть двух папок с одинаковым именем.

## Письма: messages

```javascript
{
    _id: "30000000-0000-4000-8000-000000000001",
    folder_id: "20000000-0000-4000-8000-000000000001",
    content: {
        subject: "Homework",
        body: "Project description."
    },
    recipients: ["teacher@example.com"],
    size_bytes: NumberInt(20),
    created_at: ISODate("2026-10-12T12:00:00Z")
}
```

`_id`, `folder_id`, тема и текст — String; `content` — Object;
`recipients` — Array строк; `size_bytes` — Number (BSON Int32/Int64);
`created_at` — Date. Поле `size_bytes` содержит размер текста письма в байтах UTF-8
и вычисляется сервером. Так в модели используются все типы данных из задания.

Вариант API поддерживает одного получателя. Поэтому массив `recipients` содержит
ровно один адрес, что проверяется ограничениями `minItems: 1`, `maxItems: 1`.
Клиент по-прежнему передаёт строку `recipient_address`.

Индекс `{folder_id: 1, created_at: 1, _id: 1}` используется для чтения писем папки
с сортировкой по времени и коду. Индекс `_id` MongoDB создаёт автоматически
для каждой коллекции; он нужен для поиска пользователя, папки и письма по UUID.

## Embedded documents и references

| Связь | Выбор | Обоснование |
| --- | --- | --- |
| Пользователь → папки | Reference `folders.user_id` | Папки имеют свои идентификаторы и создаются отдельно; список папок может расти |
| Папка → письма | Reference `messages.folder_id` | Писем может быть много, текст может быть большим; отдельные документы позволяют получать письмо по коду |
| Письмо → тема и текст | Embedded `content` | Эти небольшие связанные поля принадлежат одному письму и читаются вместе |
| Письмо → адрес получателя | Embedded Array `recipients` | Адрес является частью письма, отдельная коллекция адресов этому варианту не нужна |

Письма не вкладываются целиком в папку: рост массива мог бы привести к лимиту
документа MongoDB 16 MiB. Ссылки сохраняют независимые документы и простые запросы.
Для одной записи письма достаточно обычного `insertOne` или `updateOne`.

MongoDB не проверяет существование ссылок как внешний ключ PostgreSQL.
API проверяет пользователя при создании папки и владельца папки при создании
или чтении письма. Скрипт CRUD удаляет сначала письмо, затем папку и пользователя.

## UUID и совместимость API

В `_id` хранится UUID в виде строки. Это сохраняет идентификаторы, используемые
в предыдущих домашних работах. В ответах API `_id` пользователя и папки
становится `id`, а `_id` письма — `code`.

Тема и текст из `content` возвращаются как прежние поля `subject`, `body`,
первый элемент `recipients` — как `recipient_address`. Поле `size_bytes`
остаётся внутренним полем документа. Пути, HTTP-методы и модели запросов API сохранены.
BSON Date имеет точность до миллисекунд; дата округляется перед записью.

## Валидация

`validation.js` создаёт `$jsonSchema` для всех трёх коллекций:

- все перечисленные поля обязательны;
- `_id` и ссылки должны быть строками в формате UUID;
- имена, названия, тема и текст не могут быть пустыми или состоять только из пробелов;
- хеш должен быть строкой с префиксом Argon2id;
- `created_at` должен быть Date;
- `content` должен содержать строковые `subject` и `body`;
- массив получателей содержит один корректно оформленный адрес;
- размер текста должен быть целым числом не меньше 1;
- поля, отсутствующие в схеме, отклоняются.

Используются `validationLevel: "strict"` и `validationAction: "error"`.
Тесты пробуют вставить документы с пропущенными полями, пустой темой,
неверным адресом, нулевым размером и строкой вместо даты. MongoDB возвращает
ошибку `121` (Document failed validation); документы не сохраняются.

## Данные и запросы

`data.js` добавляет по 10 документов в каждую коллекцию через `$setOnInsert`
с `upsert: true`. Повторный запуск не создаёт дубликаты и не заменяет документы.

`queries.js` содержит все восемь операций варианта, а также Update и Delete
для каждой коллекции. Пример фильтра использует `$eq`, `$ne`, `$gt`, `$lt`,
`$in`, `$and`, `$or`; поиск по маскам — `$regex`.
Изменение и удаление выполняются только над документами, созданными самим скриптом.
Необязательные агрегации не используются.
